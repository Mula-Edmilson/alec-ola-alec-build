# ALEC Vision V8 — managed candidate

On Windows, select the **modified** Sigma executable (`sigma-file-manager.exe`) in Visão > ALEC Vision, enter explicit local project folders (one per line), approve, then activate and test. The supervisor pins the executable SHA-256; it will not start a changed executable. A generated 256-bit token is protected using Windows current-user DPAPI and stored at %LOCALAPPDATA%/ALEC/vision/sigma-token.dpapi. The token is never shown in the panel or stored in normal config. Sigma is started on demand, with the upstream autostart flag, using a restricted environment. An existing compatible service is reused only if the authenticated protocol and exact approved roots match. If another Sigma instance is open or scopes changed, close Sigma normally and retry; no process is forcibly terminated. Stock Sigma is incompatible. Build instructions in sigma-integration/README.md.

Optional local monitoring observes immediate directory changes (nonrecursive, counts only, events may be coalesced). It does not send filenames to a model, automatically run tasks, or replace the full Proactive engine. The existing Roamies safety gate remains in force and the supervisor adds explicit canonical scopes. No drive root, UNC path or write tool. Remote is deliberately denied until Trust has a verified device-level grant and origin proof; the Trust branch currently contains no separate implementation. Cloud model use can transmit returned metadata under existing provider settings. No extra model or duplicate index.

The Windows candidate workflow builds ALEC; Sigma requires a separate modified build. Do not install over the stable version until both candidates and real Windows end-to-end tests pass. Tests use simulated HTTP/credential protection where indicated; DPAPI and native process startup require real Windows verification.
